# 聚在一起

局域网多人聚会游戏合集。房主开个手机热点或连上同一个 Wi-Fi，其他人把地址填进去，
30 秒内就能开局——不需要注册、不需要联网、不需要服务器。

> **项目状态：开发中。** 你画我猜与 UNO 都已可局域网联机游玩；UNO 另有单机对电脑模式。

---

## 为什么做这个

市面上的聚会游戏基本都依赖在线服务：要注册、要联网、一屋子人网络不好就玩不了。
而聚会场景恰恰经常在没网的地方——露营地、KTV、桌游店、老家的客厅。

聚在一起反过来做：**把服务器放在房主的手机里**。

## 特性

| | |
|---|---|
| **零配置开局** | 房主建房显示地址，其他人填进去即可加入 |
| **完全离线** | 局域网直连，不需要互联网，不需要账号 |
| **零运营成本** | 房主手机既是玩家也是服务器，没有云端依赖 |
| **派对向设计** | 单局 3~12 分钟，随时能加人、能换游戏 |

## 快速开始

### 在电脑上运行

用 Godot 4.7 打开工程目录按 `F5`，或者用附带的脚本：

```powershell
.\tools\play.ps1
```

### 构建到手机

```powershell
# 导出调试版 APK
& 'D:\Godot Progame\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe' `
    --headless --export-debug "Android" 'build\partygames.apk'

# 安装到已连接的设备或模拟器
adb install -r 'build\partygames.apk'
```

也可以把 APK 直接拖进模拟器窗口安装。

> 首次导出前需要安装导出模板（编辑器 → 管理导出模板），并在编辑器设置里
> 填好 Android SDK 与 Java SDK 路径。详见 `docs/开发笔记.md`。

## 架构

工程分三层，依赖方向是单向的：游戏层依赖框架层，框架层不认识任何具体游戏。

```
games/      游戏层    每款游戏实现同一个 MiniGame 接口
   │
core/       框架层    连接、房间、游戏注册表、通用 UI 主题
   │
drawing/    绘制引擎  你画我猜与画猜接龙共用的画板
```

### 三条贯穿全局的设计约束

**1. 主机权威。** 房主手机运行全部游戏逻辑并做最终判定，客户端只负责表现与输入采集。
游戏规则代码只有一份，主机和客户端共用。

**2. 隐藏信息点对点单发。** 需要保密的数据（你画我猜的答案、UNO 的手牌）
绝不进广播快照，只单发给对应玩家。否则一个抓包工具就能看穿全场。

**3. 加游戏不改框架。** 游戏只声明「我支持几人、有哪些配置项」，
大厅的配置界面、游戏列表、对局装载全部据此自动生成。加一款游戏不需要改 `app/` 一行代码。

### 主要目录

```
app/                     应用外壳：选游戏 → 建房/加入 → 大厅 → 对局
core/
  net/                   传输层与协议定义
  room/                  房间控制器：握手、玩家列表、报文路由
  games_catalog.gd       游戏注册表
  ui/                    浅色主题、HSV 取色器
drawing/                 画板与笔迹二进制编解码
games/
  base_minigame.gd       所有小游戏实现的统一接口
  draw_guess/            你画我猜
  uno/                   UNO
tools/                   构建与测试脚本
data/                    词库等运行时数据
docs/                    设计与开发文档
```

## 测试

```powershell
.\tools\run_tests.ps1        # 单元测试，几秒钟
```

九套用例，共 548 项断言，覆盖规则引擎、绘制引擎、开屏与返回栈、构建配置
（含启动画面与图标）、游戏注册表与联机报文编解码。

联机部分因为要起多个进程，单独跑：

```powershell
.\tools\tests\run_net_smoke.ps1    # 连接层：握手、玩家列表、报文路由
.\tools\tests\run_net_round.ps1    # 你画我猜：打完整局，比对三个进程各自记录到了什么
.\tools\tests\run_net_uno.ps1      # UNO：跨进程打完一整局，比对三边的赢家
```

`run_net_round.ps1` 是防「两边状态不一致」类问题的关键。它起 1 个主机 + 2 个客户端
真的打完 3 回合，比对三边的结算记录、分数与公开答案是否完全一致，并检查
非画手有没有拿到不该拿的信息。这类问题在单个进程里看全是对的，
只有把两边的记录摆在一起才露馅。

### 界面截图

「屏幕显示不全」「牌压在按钮上」这类问题测试一条都拦不住——测试不看像素。
所以另有两个需要开窗口跑的截图工具：

```powershell
# 按真实比例把每个界面各截一张（设计稿 / 手机长屏 / 桌面宽窗 / 平板）
& $godot --path . --script res://tools/tests/screenshot_matrix.gd

# 把伪 3D shader 在不同旋转角下的样子排成一张对照图
& $godot --path . --script res://tools/tests/shader_probe.gd
```

两个都**不能加 `--headless`**，headless 没有渲染，截出来全是空的。图片落在 `user://`。

## 开发

### 分支约定

主干为 `main`。试验性改动开短生命周期分支，做完即并。

### 编码约定

- **`*.ps1` 必须是纯 ASCII**（有测试盯着）。PowerShell 5.1 会按系统代码页解码
  无 BOM 的 UTF-8，中文注释可能吞掉换行符并破坏脚本。
- UI 文本走 `tr()`，不硬编码在代码里。
- 新增的 `*.uid` 文件必须提交，`.godot/` 目录不要提交。

### 注意事项

工程里有几个容易踩的坑（Godot 编辑器会改写 `project.godot`、
非资源文件需要显式加进导出过滤器、安卓网络权限默认关闭等），
都记录在 [`docs/开发笔记.md`](docs/开发笔记.md)，动手前值得翻一下。
