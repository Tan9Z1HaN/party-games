# 环游中国 · 游戏规划

> 玩法参考大富翁，棋盘是中国城市。放在**聚会游戏**的语境里做，
> 所以最重要的不是「还原大富翁」，而是「压缩到一局十几分钟」。
>
> 拟注册 id：`tour`

**当前进度：第 1、2、3 步已完成**（棋盘 + 规则引擎 + 单机试玩 + 局域网联机）。
代码在 `games/tour/`，测试见 `games/tour/tests/`。
已注册进游戏列表：单机对电脑、2~6 人局域网都能玩。**第 4 步（打磨）还没做**。

### 竖屏棋盘的实际做法（第 2 步踩出来的）

规划里写的是「正方形棋盘撑满宽度」，实际做下来改成了**竖屏拉长的矩形**：

- 正方形会在竖屏上下各空一大块，格子还被压小
- 拉长之后格子高度从 93 变成 132，名字放得下，纵向也不浪费
- 经典棋盘是方的，但那是给桌面设计的；手机竖屏本来就高

另外两条：

- **格子上只放短名**（全名留给弹窗和日志），四个字是极限
- **棋盘中央那块空地放骰子和提示**——40 格围一圈，中间不放东西就是一大片浪费
- 名字画在偏上、棋子放在下半部，两者错开，不然棋子正压在名字上

### 接联机的实际做法（第 3 步踩出来的）

**比 UNO 简单**，因为它几乎没有隐藏信息：钱、地、等级、轮到谁全是公开的。
所以不用 UNO 那套「手牌单发」——房主定期广播一份完整状态快照就够，
客户端拿到的快照和别人看到的完全一样，也就不存在「两边不一致」这类问题
（UNO 和画猜那几次翻车全是隐藏信息分岔出来的）。

两条具体的做法：

- **牌桌是纯视图**：`main.gd` 只认 `_game.state()` 这份状态字典，一个字段都不从
  规则对象上读。单机和联机因此共用同一份渲染和交互代码。
- **动画靠对比前后两份快照**，不靠事件回调：位置变了就逐格跳、`dice` 变了就滚骰子、
  `card_seq` 变了就翻卡。单机自己 `submit()` 完也走同一条路径，两套逻辑不会跑偏。

退房的人**留在玩家列表里标成出局**，不抹掉：直接删掉的话，顶栏人数会悄悄少一个，
玩家只会觉得「刚才那个人怎么没了」。

## 0. 先说名字

**「大富翁」是注册商标**（Hasbro 的 Monopoly、大宇的大富翁系列）。
棋盘玩法本身不受保护，但名字不能拿来上架。所以：

- 对外名字用**《环游中国》**（备选：城市大亨、中国之旅）
- 文档里说「大富翁玩法」只是在描述玩法来源，不当作产品名

## 1. 三个决定，定下后面所有设计

大富翁天生是**两小时起步**的游戏，而本项目其他游戏都是 5~10 分钟。
不解决这件事，做出来就是「没人愿意开局的那个选项」。三件事先定：

| 决定 | 取值 | 为什么 |
|---|---|---|
| **胜利条件：把别人搞破产** | 最后只剩一个人没出局 | 这才是大富翁的博弈：买哪块、升到几级、敢不敢把钱花光，每一步都在赌。**「打满几轮比资产」试过，没意思**——没有破产压力，中后期就是各走各的 |
| **回合上限只当保险丝** | 默认不限（0） | 破产制可能拖长，留一个上限防止无限拖。正常局走不到它 |
| **每人每回合限时** | 25 秒（可配 15/25/40） | 没有限时，一个人想买地想三分钟，全场都在等 |

> **改动记录**：第一版做的是「固定轮数 + 资产排名」，实机玩下来觉得没意思
> （见上面那条）。改成破产制之后，最大的工作量不在规则，而在**经济模型**——
> 见 3.3 节，租金和补贴的比例直接决定一局是 20 轮还是 390 轮。

人数：**2~6 人**。上限压到 6 而不是 8，是因为大富翁是**轮流制**，
8 个人等一轮太久了。

## 3. 一局怎么走

### 3.1 回合流程

```
掷骰（2 个骰子）→ 前进 → 落点结算 → 可选的经营动作 → 下一位
```

掷骰由**房主**执行（防作弊），点数广播给所有人。

### 3.2 落点结算

| 落在 | 结果 |
|---|---|
| 无主地 | 可以按地价买下。**不买就过去**，没有拍卖 |
| 自己的地 | 可以升级（最多 4 级） |
| 别人的地 | 付过路费 |
| 落在自己的整组 | 租金翻倍 |
| 机会 / 命运 | 抽一张卡，立即生效 |
| 税 | **个人所得税二选一**：交固定 200，或交总资产的 10%；奢侈税固定扣 100 |
| 进滞留 | 移到滞留格，下一轮暂停一次（或交 100 立即离开） |
| 出发 | 经过 +200，停在上面也 +200 |

### 3.3 经济模型（这一节决定一局有多长）

**破产制之下，租金和补贴的比例就是一局的长度。** 这条是量出来的，不是拍的：

```
绕圈补贴 = 100            ← 全局收入的主要来源
起始资金 = 600            ← 一根引线有多长
基础租金 = 地价 × 0.25    ← 地大多停在低级别，所以这一项是过路费的主力
每升一级 × 3.0            （1 → 2 → 3 → 4 级）
垄断加倍 × 2              （同组全都归你）
升级费用 = 地价 × 0.5 每级
```

| 等级 | 名字 | 租金（以 200 的地为例） |
|---|---|---|
| 1 | 空地 | 50 |
| 2 | 开发 | 150 |
| 3 | 楼盘 | 450 |
| 4 | 地标 | 1350 |

**调这几个数之前先看这张表**——同样的规则，两组数字差出一局的十倍：

| 补贴 / 起始资金 / 基础租金 | 4 人局实测长度 |
|---|---|
| 200 / 1500 / 0.10 | **390 轮**，谁都破不了产 |
| 150 / 1000 / 0.10 | 195 轮 |
| 100 / 800 / 0.15 | 220 轮 |
| 100 / 600 / 0.25 | **20 轮** ✓ |

前两行的毛病是**收入盖过支出**：绕一圈 +200，而地大多停在 1~2 级
（升级要钱），过路费一次才二三十——大家都在慢慢变富。

- **高铁枢纽**：固定租金 250，升级到 2 级 500
- **公用事业**：固定租金 200，升级 500
  （不做经典那套「按骰子点数算」，手机上看不清）

**所得税做成经典的二选一**（交固定 200 / 交总资产 10%）：固定值前期划算，
比例后期划算，正好把前后期都照顾到，也给玩家一个真正的决策点——
「我现金少但地多，该交哪个」。奢侈税没有二选一，直接扣 100。

用公式而不是手写表，是为了让「调价格」变成改一个系数，
而不是改 22 行数字再逐个检查。

### 3.4 出局与结算

```
现金被扣成负数 → 出局，名下的地全部释放（别人以后可以买）
只剩一个人没出局 → 他赢，本局结束
```

不做抵押和赎回：那是给两人长局设计的，聚会场景没人有耐心算。
「付不出来就出局」既简单又快，还给对手一个干净的目标——**把他逼到付不出钱**。

回合上限（如果开了）到点时，按总资产 = 现金 + 地产成本排名，
但那是保险丝，不是常规结局。

## 4. 砍掉了什么，为什么

这一节比上面的规则更重要——**该砍的地方不砍，游戏就不好玩**。

| 砍掉 | 理由 | 代价 |
|---|---|---|
| **玩家间自由交易** | 大富翁最花时间的环节：讨价还价三轮，半小时就没了 | 少了博弈深度。补救：把垄断收益调高，让「自己集齐」成为可行目标 |
| **拍卖** | 不买就过去，节奏干净 | 少了「别人抬价」的乐趣 |
| **抵押 / 赎回** | 需要一套负债状态机，手机上操作也繁琐 | 破产判定简化成「现金为负即出局」 |
| **房屋/旅馆的存量限制** | 需要一套存量池，收益不明显 | 后期可能出现满地图地标 |
| **固定轮数 / 资产排名** | **试过，回头改了**：没有破产压力，中后期就是各走各的 | 改成破产制（见第 1 节） |

> 注意「砍掉交易」和「破产制」是一对矛盾：经典大富翁里交易是凑成整组、
> 把租金推到高位的主要手段。砍掉交易之后，**租金得靠升级顶上去**，
> 所以 AI 和玩家都得愿意升级——这就是 3.3 节里那组数字的由来。

## 5. 卡片：文案方向与红线

机会（偏收益）和命运（偏损失）各 12~16 张。**文案要短**——
手机上一行字，超过 12 个字就读不完了。

方向上走**出行 / 消费 / 网红**这三类生活场景：

- 高铁提速：前进 3 格
- 走错航站楼：后退 2 格
- 网红打卡火了：收 200
- 直播带货翻车：付 150
- 景区排队：暂停一次
- 天气原因延误：移到最近的滞留格

**红线**：不写调侃政策、政府部门、地域歧视、灾害的内容。
这类梗在熟人局里可能觉得好笑，但装到应用商店里就是风险，
而且聚会里可能有你不熟的人。**中性、无害、好笑**是标准。

## 6. 界面：竖屏怎么塞下一张棋盘

这是这个游戏最大的界面风险。40 格的方形棋盘放到 1080 宽的竖屏上，
每格只有一侧边长的一半——**名字和价格根本读不清**。

### 6.1 方案：棋盘整体可见 + 点击看详情

```
┌──────────────────────────┐
│ 玩家条（头像·现金·资产）  │  ← 顶部固定
├──────────────────────────┤
│        ┌──────────┐      │
│        │   棋盘    │      │  ← 正方形，撑满宽度
│        │  (40 格)  │      │
│        │   中央    │      │  ← 骰子 + 当前卡片 + 提示
│        └──────────┘      │
├──────────────────────────┤
│  买下 / 升级 / 放弃       │  ← 底部按钮，随落点变化
└──────────────────────────┘
```

- 每格**只写两三个字**（「上海」「西安」），价格用颜色深浅表示档位、不写数字
- 格子底色 = 所属组；有主的格子加一圈玩家色描边，等级用角上的小点表示
- **点任意格子弹出详情**（地价、等级、业主、当前租金）
- 中央区域是信息中心：骰子动画、当前卡片文案、当前玩家的提示

### 6.2 棋子与动画

棋子是**最多 6 个小圆点**，同格时按角度散开，不要叠在一起。
移动用**逐格跳动**（一格一跳，每跳 0.08 秒），不要一次滑过去——
逐格跳能让玩家看清经过了哪些格子（尤其「经过出发」）。

伪 3D 那套（`ui/fake3d.gdshader`）可以用来做**棋子的落下放大**和
**卡片翻出来**。骰子不要用伪 3D：那个 shader 是单面透视，做不了立方体。
用 2D 精灵 + 快速切点 + 抖动就够了，读起来一样是「掷骰子」。

## 7. 技术设计：复用现有框架

目录和 UNO 一个形状，四层分工不变：

```
games/tour/
  board.gd        棋盘数据：40 格（名字/组/地价），纯常量，不依赖 UI
  rules.gd        规则引擎：走格、买地、升级、收费、破产、结算（纯逻辑）
  ai.gd           AI：买不买、升不升级（先做贪心，够用）
  messages.gd     报文
  game.gd         MiniGame 适配（房主权威 + 客户端镜像）
  main.gd         棋盘视图
  ui/             棋子、格子、骰子、资产面板
  tests/          单测 + 冒烟 + 联机
```

**直接照搬 UNO 已经踩通的那套**：

- **状态字典是唯一数据源**，`main.gd` 只认它，不认规则对象
- 房主权威：掷骰、收费、破产判定全在房主
- **公开信息走广播**：大富翁几乎没有隐藏信息，所以不需要 UNO 那套
  单发手牌，快照就是完整状态，客户端实现比 UNO 简单
- AI 托管更容易做（没有隐藏信息），可以顺手一起做掉

**新增的、UNO 不需要的东西**：

- `board.gd` 的数据表（UNO 的牌是程序生成的，这里要手写 40 行）
- **回合计时器**：25 秒超时自动跳过
- 资产汇总（UNO 结算只用牌面分）

注册进 `core/games_catalog.gd` 就行，大厅和配置界面会自动长出来
（配置项：轮数、每回合秒数、起始资金、是否开启卡片）。

## 8. 测试策略

沿用现有四套的写法，重点在**规则引擎能被穷举**：

| 套件 | 测什么 | 关键用例 |
|---|---|---|
| `rules` 单测 | 纯逻辑 | 走格与绕圈、经过出发加钱、租金公式、垄断加倍、升级上限、破产判定、固定轮数结算 |
| `game_layer` | 联机协议 | 快照/事件编解码、房主校验非法操作、客户端镜像与房主一致（照抄 UNO 的整局比对） |
| `smoke_scene` | 界面 | 40 格都建出来了、掷骰动画期间不能重复操作、落点弹窗、结算页排名 |
| `run_net_tour.ps1` | 跨进程 | 1 主机 + 2 客户端打完整局，比对三边的**最终资产排名** |

**骰子要能注入随机种子**：给定序列就能复现「走到某格 → 买到 → 落到对手
地上 → 破产」这些具体情境。UNO 的 `UnoRules.setup(..., seed_value)`
已经这么做，照抄。

## 9. 分四步做

和 UNO 一样，每一步都能单独验收：

| 步骤 | 内容 | 验收 |
|---|---|---|
| **1. 棋盘 + 规则引擎** | `board.gd` 40 格、`rules.gd` 全部判定、单测 | 单测能让 AI 对 AI 跑完一整局，资产结算正确 |
| **2. 单机试玩** | 棋盘渲染、骰子、棋子移动、买地/升级交互、AI 对手 | 手机上一个人能和一两个 AI 打完一局，界面读得清 |
| **3. 接联机** ✅ | `game.gd` + 报文 + 大厅配置 | 2~6 人真机开局，跨进程整局测试通过 |
| **4. 打磨** | 卡片文案、动画节奏、结算页、音效 | 一局 8 轮的实测时长落在 10~15 分钟 |

**第 1 步最大**（规则引擎 + 40 格数据），也最值得先做：
它没有界面依赖，能纯靠单测把逻辑钉死，后面两步都是接壳。

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| **时长压不下来** | 做完了没人愿意点，本末倒置 | 第 1 步就把「固定轮数 + 限时 + 资产排名」做进去；第 2 步立刻实测一局时长 |
| **竖屏读不清** | 玩家看不懂局势，全程在问「这是谁的」 | 第 2 步先做棋盘原型用真机看；不达标就减格子（40 → 28 格）或放大中央信息区 |
| **交易被砍后策略变浅** | 中后期变成「谁运气好谁赢」 | 提高垄断收益、加「集齐整组才能升到 4 级」这类约束，把决策压到「买哪块」上 |
| **商标** | 上架被拒或被投诉 | 名字不用「大富翁」；美术不抄任何现成棋盘的视觉 |
| **文案踩线** | 商店审核、玩家观感 | 卡片文案走生活场景，不碰政策/地域/灾害 |

## 11. 需要你拍板的四件事

1. **名字**：《环游中国》可以吗？备选：城市大亨 / 中国之旅
2. **人数上限**：6 人（推荐）还是 8 人？8 人会让等待明显变长
3. **要不要交易**：先砍掉（推荐），还是保留一个简化版
   （「出价买对方一块地，对方接受或拒绝」）
4. **棋盘格数**：先按 40 格做，还是直接做 28 格的紧凑版？
   40 格更经典，但竖屏更挤

这四个定了，就可以从第 1 步（棋盘数据 + 规则引擎 + 单测）开始。
