记录工程实践中踩过的坑与得出的结论。这些不是理论，都是实际撞过、排查过的。

按「什么时候会遇到」分组，动手前扫一眼能省不少时间。

## 一、Godot 编辑器相关

### 编辑器会改写 `project.godot`，并且会吃掉你的注释

在 `project.godot` 的设置项之间写注释，编辑器保存时会把**相邻的注释行合并进
后面那个键名**，生成一条乱码项，并顺手删掉真正的设置。

实际丢过 `window_width_override` 和 `rendering_method.mobile`。

**结论**：不要往 `project.godot` 里写注释（文件顶部那块标准文件头是安全的），
说明写到文档里。改这个文件前先关掉编辑器。

### 启动时会先闪一下 Godot 的引擎 logo

项目里没配 `application/boot_splash/*` 的话，用的就是 Godot 默认那张引擎
logo 动画；安卓导出那边还有一条独立的 `splash_screen/disable_godot_boot_splash`
要关。两处都漏着的话，启动时会先看到引擎 logo，再切到应用自己的浅蓝紫底，
中间那一下非常出戏。

现在的配置是：关掉启动图，底色设成和 `LightTheme` 渐变起点一致的浅色
（`Color(0.83, 0.89, 1)`），加载完接上去看不出接缝。

**这条有回归测试盯着**（`tools/tests/export_config.gd`）。原因就是上面那条：
编辑器改 `project.godot` 时会整段重写，手改的配置很容易被悄悄抹掉。

### 非资源文件不会被打进导出包

Godot 只打包它认识为资源的文件。`.txt`、`.json` 这类没有导入器的文件，
必须在导出预设的 `include_filter` 里显式列出（本项目是 `*.txt,*.json`）。

**症状**：编辑器里一切正常，装到手机上功能直接失效。

### `*.csv` 会被当成翻译表导入

Godot 有 CSV 导入器，会把 CSV 当翻译表处理并生成 `.translation` 文件。
更麻烦的是**被导入的源文件不会被打包**——所以词库不能叫 `.csv`，
本项目用的是 `.txt`。

### 合并分支后要先跑一次导入

`.godot/` 里缓存着全局类名。合并进来的新脚本如果没被扫描到，
所有引用它们的脚本都会报 `Failed to compile depended scripts`。

**结论**：合并后先跑一次 `--headless --import`，再跑测试。

### 编辑器数据目录不可写时，Godot 会直接崩

如果 `%APPDATA%\Godot` 不可写，引擎在创建 `user://logs` 失败后会**空指针崩溃**
（访问违例）。受限环境里把 `APPDATA` / `LOCALAPPDATA` 指到可写目录即可。

顺带一提：这种情况下 Godot 会把 `export_templates/`、`feature_profiles/` 等
目录建到工程根目录，记得删掉，别提交。

## 二、安卓导出

### `permissions/internet` 默认是 `false`

Godot 新建导出预设时会把**所有安卓权限都默认填成 false**，包括网络权限。
没有它，任何 `create_server` / `create_client` 都会失败。

**症状**：编辑器里一切正常，装到手机上建房直接失败。

本项目已在 `export_presets.cfg` 里打开，并有测试盯着。

### 单机游戏也要 JDK

Android 导出需要 JDK。Android Studio 自带的 JBR 可以用，但版本较新时
可能和 Godot 的 Gradle 版本冲突——本项目选择**不走 Gradle 构建**规避这个问题。

## 三、Windows 与脚本

### `*.ps1` 必须是纯 ASCII

Windows PowerShell 5.1 按系统 ANSI 代码页解码 `.ps1`（无 BOM 的 UTF-8 也不例外）。
中文会变乱码；更糟的是那种代码页是双字节的，**注释末尾半个汉字会把换行符吞掉**，
下一行代码直接进了注释，整个函数断掉。

**结论**：构建脚本一律纯 ASCII，中文写进 `.md`。本项目有测试扫描 `tools/**.ps1`。

### 不要用 `$Args` 当参数名

PowerShell 有自动变量 `$args`，名字撞上之后函数里读到的是那个空的自动变量，
传进来的参数**静默消失**——不报错，只是参数没了。

### `Start-Process` 在特定环境下会抛异常

它重建环境块时会撞上 `Path` / `PATH` 大小写重复键，
报「已添加项。字典中的关键字」。

**结论**：直接构造 `System.Diagnostics.ProcessStartInfo`，并且不去碰
`EnvironmentVariables`，让环境块原样继承。

## 四、GDScript 语言细节

### `const` 里不能用构造函数

```gdscript
const COLORS := PackedColorArray([Color(1, 0, 0)])   # ✗ 不是常量表达式
const COLORS := [Color(1, 0, 0)]                     # ✓
```

用错时 const 声明本身不报错，**引用处**才报
`Could not resolve external class member`——很难定位。

### lambda 按值捕获局部变量

```gdscript
var result := []
signal_x.connect(func(v): result = v)   # ✗ 改的是副本，外面看不到
```

数组这类引用类型 `append` 是生效的，但**赋值**不生效。要传值出来就用成员变量。

### 不在场景树里的节点拿不到 `multiplayer`

`Node.multiplayer` 依赖 `SceneTree`。节点不在树里时，
判断「本机是不是权威端」会得到错误答案。构造出来的游戏对象一定要 `add_child`。

### RPC 依赖 NodePath 两端一致

路径不一致时 RPC **静默失败**——不报错，只是收不到，是最难排查的一类问题。

本项目的做法：房间场景自包含，所有 RPC 挂在固定路径 `/root/Main/Room` 上，
运行期不增删该节点下的节点。

## 五、界面

### `Button.flat = true` 会让它不画 normal 样式框

如果靠 `normal` 样式框上色（比如色块按钮），设了 `flat` 就是一排透明方块。

### 浅色主题下别用 `CheckButton`

它的勾选图标来自默认深色主题，铺在浅色底上几乎看不见。
用带 `toggle_mode` 的普通按钮代替。

### 只改 `font_color` 是不够的

按钮的 hover / pressed / focus / disabled 各有独立的颜色，
漏一个就会在按下或禁用时重新变得看不清。按钮底色也来自主题，不换的话黑字压深灰更糊。

### GDScript 提示：整数除法有警告

`card / 16` 会触发整数除法警告。位运算既没警告、意图也更清楚：
`card >> 4`、`card & 0x0F`。

## 六、流程上的教训

### 「说修好了」不等于修好了

期间发生过一次：把多个改动打包成一个补丁，其中一部分没匹配上、整个补丁失败，
拆开重打时漏掉了一段，却在提交信息里写了「已修好」。

**结论**：修完要验证，尤其是「已修复」这种断言。本项目现在对每个修过的 bug
都补一条回归测试。

### 改一处别忘了另一处

同一个操作如果有多个入口（比如你画我猜的五条输入路径），
改了一个忘了另一个，症状是「功能静默失效」。

**结论**：这类问题只有跨进程的整局测试能拦住，所以有了 `run_net_round.ps1`。

### 测试通过 ≠ 程序能启动

单元测试全绿的情况下，应用仍然可能因为启动期的空值报错而打不开。
本项目现在除了单元测试，还会跑一次「应用外壳启动」检查。

## 七、UNO 的伪 3D

### 为什么 shader 方案要求先烘贴图

参考项目（Hei 的 Godot4-Fake3D-Card-Game-UI-Demo，MIT）在 canvas_item 的
vertex 里自己搭旋转矩阵、在 fragment 里做透视除法，看起来是立体的。
这套数学要求 shader 的 `TEXTURE` 真的是一张牌面贴图。

而本项目的牌原本是 `Node2D._draw()` 画出来的：文字走字体图集、多边形走白点图，
**没有「一张贴图」这个概念**，透视数学套不上去。所以先把自绘结果渲染进
`SubViewport`（见 `ui/card_art.gd`），取出来当贴图用。只在第一次进牌桌烘一次，
之后一直命中缓存。headless 下没有渲染，退回纯色占位图——测试只验逻辑，不看像素。

顺带一个好处：牌面留在代码里，改配色直接看效果，不用「改脚本 → 重跑烘焙 → 提交 55 张图」。

### 实测出来的两条边界

`inset` 参数只等价于整体缩放，改它不会改变形状，控制大小用 `node.scale` 就行。

**绕竖轴的 `y_rot` 不能超过约 ±70 度。** 接近侧对镜头时投影的 z 趋近 0，
透视除法会把牌拉成一条巨大的竖条：90 度整张消失，135 度直接炸开。
手牌扇形的每格转角是按「最外侧不超过 42 度」反推的。
这类结论推导不出来，`tools/tests/shader_probe.gd` 把各个角度排成一张对照图，看一眼就清楚。

### 牌背为什么会变成一块灰方块

牌背 sprite 最初照着参考项目把 `y_rot` 减了 180 度，好让正面转到背面时露出牌背。
但牌背贴图本身是「正面朝上」画出来的，减 180 度等于把它翻到了背面，
被 shader 的 `cull_back` 剔掉——整张牌就只剩阴影，看上去是一块灰色方块。

**结论**：不用翻面动画时，就不要给牌背额外转 180 度；哪一张显示交给 `visible` 决定。
另外 `cull_back` 直接关掉，避免任何角度下整张牌静默消失。

### 窗口比例是「只会变大」的

`project.godot` 用的是 `canvas_items` + `expand`，所以**可见区域永远不会小于
设计稿的 1080x1920**，只在某一个方向上变大。桌面窗口被屏幕高度限制时，
换来的不是更矮的视口，而是更宽的可见区域（本机是 1465x1920）。

所以「1080x1415 的矮窗口」这种情况测不出问题，别照着它去调布局。
`tools/tests/screenshot_matrix.gd` 列的是真实可能出现的形状。

### 底部按钮被手牌盖住

卡牌是 `Node2D`，z_index 在 0~90；界面控件是 `Control`，z_index 默认 0。
于是手牌永远画在按钮上面——按钮看得见摸不着。
给 UI 容器一层的 `z_index` 抬到 100 以上（选色面板 200）解决。

布局上还留了固定的上下安全带（`TOP_RESERVE` / `BOTTOM_RESERVE`），
并且把手牌扇形最外侧往下掉的那部分也算进安全带里，
否则屏幕比例一变，边上的牌就又压到按钮上了。这条有回归测试盯着。

## 八、UNO 接联机

### 界面只认「状态字典」，不认规则对象

接联机之前，`main.gd` 是规则和视图揉在一起的：本地玩家点牌直接调
`_rules.play_card()`，AI 回合也由它驱动。单机没问题，但客户端不能跑规则。

现在分成三层：

```
main.gd      纯视图。输入只走 _game.submit(报文)，状态只从 _game.state() 读。
uno_game.gd  房间层适配。房主跑规则、收意图、广播公开状态、单发每个人的手牌；
             客户端不跑规则，只把主机发来的东西套上。
rules.gd     纯逻辑，这一层完全不知道有没有网络。
```

`state()` 返回的那份字典是唯一的数据源——单机时它从本地规则生成，联机时
从主机报文生成。界面只认它，就不会出现「单机版和联机版长得不一样、
改一个忘一个」。

### 手牌只单发，动作走广播

`messages.gd` 里两类通道分得很清楚：

- **广播**（出牌 / 摸牌 / 日志）谁都能看，用来放动画；
- **单发**（手牌 / 拒绝原因）只给某一个人。

熟人局作弊风险低，但手牌广播出去之后，一个抓包工具就能看穿全场，
而单发的成本几乎为零。

顺序也有讲究：**先推状态和手牌，再发动画事件**。两者走同一条可靠通道，
顺序反过来的话，客户端会在手牌还没更新时就去放「牌从手里飞出去」的动画，
出现一张牌同时在手牌里和在空中的重影。

### 两个静默失效的坑

**`_is_networked()` 的守卫会把客户端那条路挡在测试之外。**
原本 `_push_hands()` 和 `_event()` 都用「有没有联网」做判断，单机时跳过。
听起来很合理，但测试环境没有 multiplayer peer，于是客户端那条路永远走不到——
结果里面藏着一个 `Array` 赋给 `Array[int]` 的类型错误，手牌一直静默是空的。
去掉守卫，让信号该发就发（没人接本来就是零成本），路径才测得到。

同理，`apply_snapshot()` / `on_remote_message()` 开头的权威端守卫也让客户端
路径测不到，所以和参考实现一样拆出了 `_apply_snapshot_data()` /
`_apply_remote_message_data()` 专门给测试用。**这个坑踩过第二次了。**

**客户端忘了 `bind_room()`，点什么都纹丝不动。**
客户端要把操作转发给房主，靠的是 `_game.bind_room(room)`。忘了这一步，
`submit()` 会走进「单机」分支，而在客户端上 `on_player_input()` 又因为不是
权威端直接返回——整条链路静默失效。现在这种情况下会 `push_error` 喊出来。
多进程联机测试第一次跑就卡在这儿：三个进程里只有房主在自己动。

### 联机测试怎么写才有意义

`tools/tests/run_net_uno.ps1` 起 1 个主机 + 2 个客户端，**真的打完一整局**：
每个进程只在自己的回合出牌，报文走 ENet，最后各进程报出自己看到的赢家，
由外层脚本比对三边是不是同一个。

单进程测试永远发现不了这类问题：房主那边是对的，客户端显示的是错的，
只有把两边的记录摆在一起才露馅。

写这个测试还顺手抓出一个死循环：选色阶段传 `active_color()` 当颜色用，
而万能牌待定的那一刻它就是 `WILD(=4)`，合法颜色只有 0~3，于是每一步都被拒。
现在测试里带了「连着几步状态一点没动就判定卡住」的检测，不用干跑到几千步。

## 九、安卓的返回键

Godot 的默认行为是**按一下返回键直接退出应用**（受
`application/config/quit_on_go_back` 控制，默认开）。手机上误触一下，
整个房间就没了，连确认都没有。

现在的做法：关掉自动退出，返回键交给 `Window.go_back_requested` 信号，
由 `app.gd` 沿界面栈往回走一层——

```
选游戏 → 菜单 → 大厅 → 对局        （返回就是倒着走）
```

已经在「选游戏」那一屏了，再按才真的退出。

### 容易接错的两个地方

**信号在 `Window` 上，不在场景节点上。** 一开始想自己写个脚本挂到根 Window
去转发 `NOTIFICATION_WM_GO_BACK_REQUEST`，结果发现 Godot 4 的 `Window` 本来
就有 `go_back_requested` 信号，而且它只在根窗口上发。用
`get_window().go_back_requested` 接就对，往场景里的节点上接则永远收不到。

**别忘了关 `quit_on_go_back`。** 这一项在，引擎会在你处理之前就把应用退掉；
这一项不在，返回键什么都不做（比退出更难发现是配置问题）。

桌面上没有返回键，所以同一段逻辑也接到了 Esc（`ui_cancel`）上，
调试返回栈时不用插手机。

### 为什么给这段单独写了一套测试

返回键的行为只有装到真机上才碰得到，而试错成本是「按一下就没了」。
所以把界面栈的走法钉在 `tools/tests/app_shell.gd` 里（选游戏 → 菜单 →
大厅 → 对局，每一层都验「返回吃掉事件 + 退到上一层」），真机上剩下的
只有「Window 的信号接上了没有」这一件事。

## 十、应用图标

### SVG 里不能写 `<text>`

Godot 用 ThorVG 光栅化 SVG，**它不支持 `<text>` 元素**。图标里写文字的话
会静默渲染成一片空白——编辑器里看不出来，只有装到手机上盯着桌面图标才发现。

所以 `tools/gen_icon.ps1` 把四个字转换成**字形轮廓**再写进 SVG：用 GDI+ 的
`GraphicsPath.AddString` 取到曲线，导出成 `<path>`。字体的依赖只存在于
生成阶段，提交进仓库的 SVG 自带轮廓，游戏运行时不需要任何字体。

### GDI+ 的 `PathTypes` 解读有歧义，先展平再说

`GraphicsPath.PathData` 给每个点配一个类型字节，但「贝塞尔的控制点算在哪个
字节上」这件事文档写得含糊。第一版按「类型描述到达这个点的线段」去解，
解出来的控制点飞到了字形外面（`C 193.75 162.89 ...`，而字形只有 100 宽）。

**结论**：曲线交给 `GraphicsPath.Flatten()` 展成折线，之后只剩「移动」和
「直线」两种类型，没有歧义。图标尺寸下肉眼看不出区别，而且仍然是矢量——
放大到启动图标那样的大尺寸依旧清晰。

### 换个角度验证图标

光看 `.svg` 文件是看不出渲染结果的，所以 `tools/tests/icon_preview.gd`
把它按 Godot 实际渲染的样子导出成 PNG 供人眼确认；
「渲染出来是不是空白」则由 `tools/tests/export_config.gd` 自动盯着
（数不透明像素和深色像素的比例）。

### 安卓会裁掉图标的边角

安卓的自适应图标分两层（前景 / 背景），系统**只保证中间那圈可见**，
各家启动器再按自己的形状裁（圆、圆角方、水滴……）。只给一张普通图标的话，
形状一裁，内容的边角就被切掉——「四个字边缘被遮住」就是这个原因。

修法是两层都给：前景只放内容、背景只放底色，内容缩进安全区。
**关键是"安全区"到底多大**：可见区域是直径 2/3 的圆，而四个字排成正方形
且笔画一直顶到方框角上，所以正方形必须内接于这个圆——
内容占比 = 0.667 / √2 ≈ 0.47。

算出来还不够，`tools/tests/export_config.gd` 会把前景层**每个不透明像素**
到中心的距离都量一遍，超过安全半径就直接失败。第一版按 0.58 生成时它报了
「最远的像素离中心 176.8，安全半径 144.0」——肉眼看不出来的问题，量一下就有数。

### 启动黑屏 / 启动图标

安卓 12 起系统**强制**有启动画面，应用去不掉它。能控的只有两件事：
背景色，以及画面上的那个图标。

- 背景色设成和 app 一致的浅色（`screen/background_color`），
  不然首帧之前会闪一下黑；
- 图标换成一张**全透明**的 PNG（`splash_screen/icon`），
  启动时就只剩一片底色，看起来像"直接打开了应用"。

留空的话系统会拿应用图标当启动画面——那正是之前看到的那一屏。

### 改应用名会连带改掉 `user://` 的目录

`user://` 落在 `%APPDATA%\Godot\app_userdata\<config/name>\`，所以改
`project.godot` 的 `config/name` 会把用户数据目录一起换掉。
旧的 `PartyGames\` 会留在原地，不会被删。

另外：安卓的 `package/unique_name`（应用的唯一标识）和 launcher 上显示的
`package/name` 是两回事。只改后者的话是**覆盖安装**，不是装成一个新应用。
